# Mini NPU Simulator

## 1. 실행 방법
실행 환경
- Python 3.8 이상 (개발: Python 3.9.6, macOS)
- 외부 라이브러리 없음 (표준 라이브러리 `json`, `time`만 사용)

**저장소 받기**
```bash
$ git clone https://github.com/hevel124/codyssey-ai-e1-3.git
$ cd codyssey-ai-e1-3
```

**실행**
```bash
$ python3 main.py
```
- 모드 선택: `선택:`에 `1`(사용자 입력 3×3) 또는 `2`(data.json 분석) 입력. 그 밖의 값은 `1 또는 2를 입력하세요.` 출력 후 다시 입력
- 모드 1: 필터 A · 필터 B · 패턴을 차례로 한 줄씩(공백 구분, 줄마다 숫자 3개) 3줄씩 입력
- `data.json` 위치: 저장소 루트(`main.py`와 같은 폴더). 프로그램은 실행한 폴더의 `data.json`을 읽으므로 저장소 루트에서 실행

## 2. 구현 요약
**라벨 정규화 방식**
- 표준 라벨 2개: `Cross`, `X`
- `normalize_label`: 값을 소문자로 바꾸고 앞뒤 공백을 지운 뒤 `+`·`cross` → `Cross`, `x` → `X`. 그 밖의 값은 `None`
- 필터 키(`cross`, `x`)와 패턴의 `expected`(`+`, `x`)를 모두 이 함수로 바꾼 뒤 출력·PASS/FAIL 비교
- 표준 라벨로 바꿀 수 없는 `expected`는 그 케이스만 `FAIL (알 수 없는 expected 라벨: …)`

**MAC 연산 구현 개요**
- `mac(pattern, filt)`: 이중 `for` 반복문으로 n×n 칸을 한 번씩 돌며 같은 위치 값끼리 곱해 `total`에 누적, 점수(float) 반환
- `flatten(matrix)` · `mac_flat(pattern, filt)` (보너스 B1): 2차원 리스트를 줄 순서대로 이어 붙여 길이 N²의 1차원 리스트로 바꾸고, 한 겹 반복문으로 `pattern[k] * filt[k]`를 누적. 성능 분석에서 `mac`과 비교
- 모드 2: 패턴 키 `size_{N}_{idx}`에서 N을 꺼내 `size_N` 필터 선택 → Cross 필터 · X 필터와 각각 MAC
- 계산 전 검사(`check_case`): 키 형식 · 필터 존재 · `input`/`expected` 존재 · 라벨 · 패턴과 필터 크기(N×N) · 칸 값이 숫자인지. 문제가 있으면 그 케이스만 원인 메시지와 함께 FAIL, 다음 케이스 계속 진행
- 파일 구조 검사: 최상위 · `filters` · `patterns`가 객체(`{}`)가 아니면 `data.json 구조 오류` 메시지 출력 후 모드 2 종료

**동점 처리 정책(epsilon)**
- `EPSILON = 1e-9`
- `judge`: `abs(score_a - score_b) < EPSILON`이면 동점 `UNDECIDED`, 아니면 큰 쪽 라벨
- 모드 1은 동점이면 `판정 불가`, 모드 2는 `UNDECIDED`를 expected와 다른 것으로 보고 `FAIL (동점 규칙)`

**FAIL 케이스 원인 분석**
- 실패 3개(`size_5_1`·`size_13_2`·`size_25_1`) 모두 수치 비교 문제(부동소수점)
- `size_5_1`: Cross 점수는 1.0 × 0.9를 한 번 더한 `0.9`, X 점수는 0.1을 9번 더한 `0.8999999999999999`. 수학적으로는 둘 다 0.9인 동점
- 0.1처럼 2진수로 끝나지 않는 값은 근사값으로 저장되어, 여러 번 더하면 아주 작은 오차가 쌓임. 세 케이스 모두 두 점수 차이가 1e-9보다 작음
- epsilon 정책에 따라 세 케이스는 `UNDECIDED`가 되고, expected(`X`·`Cross`)와 달라 `FAIL (동점 규칙)`
- epsilon 없이 `>`로 비교했다면 오차 방향에 따라 `size_5_1`·`size_25_1`은 Cross, `size_13_2`는 X로 판정되어 세 케이스 모두 expected와 반대 라벨로 FAIL. 즉 오차가 판정을 정하게 되므로 epsilon 비교가 필요
- 데이터/스키마 문제 없음: 패턴 키 6개가 모두 `size_{N}_{idx}` 형식이고, 패턴·필터 크기가 모두 N×N으로 일치, `expected`(`+`, `x`)와 필터 키(`cross`, `x`)는 정규화 후 `Cross`·`X`로 비교됨
- 로직 문제 없음: 점수 차이가 큰 3개(`size_5_2`·`size_13_1`·`size_25_2`)는 모양이 맞는 필터 점수가 커서 모두 PASS

**성능 표 해석과 O(N²) 근거**
- `mac`은 N×N 칸마다 곱셈 1번 → 연산 횟수 N² (9 · 25 · 169 · 625)
- 반복문이 두 겹(줄 N개 × 칸 N개)이므로 시간 복잡도 O(N²)
- 측정: 크기마다 `mac`만 10회 실행한 평균(ms). 입력·출력·파일 읽기는 측정 구간 밖
- 13×13 → 25×25: 연산 횟수 약 3.7배(169 → 625), 평균 시간 약 3.5배(0.0167 → 0.0581 ms). 크기가 클수록 시간이 연산 횟수에 비례해 늘어남
- 3×3 → 25×25: 연산 횟수 약 69배, 시간 약 39배. 시간 증가 배수(약 39배)가 연산 횟수 증가 배수(약 69배)보다 작음. 작은 크기에서는 함수 호출·반복문 준비 같은 크기와 무관한 고정 시간의 비중이 크기 때문
- 측정값은 실행할 때마다 조금씩 달라지지만, 크기가 커질수록 시간이 늘어나는 순서는 같음

**1000×1000 처리 시 이슈와 우선 최적화**
- 연산 횟수: 1000² = 1,000,000번. 25×25(625번)의 1,600배
- 시간: 같은 `mac`으로 1000×1000을 측정하면 MAC 1회 약 96 ms(10회 평균, 개발 PC 기준). 필터 2개 × 10회 반복이면 크기 하나에 약 2초
- 메모리: 파이썬 리스트는 칸마다 실수 객체를 따로 만들어 1000×1000 배열 1개에 약 31 MB(측정값). 패턴 1개 + 필터 2개면 약 94 MB
- 우선 최적화: 2차원 리스트를 길이 N²의 1차원 리스트로 바꿔 `pattern[i][j]`(인덱싱 2번)를 `pattern[k]`(1번)로 줄이고 반복문을 한 겹으로 단순화. `mac_flat`으로 구현했고, 1000×1000에서 MAC 1회 약 96 ms → 약 73 ms(10회 평균, 개발 PC 기준)
- 한계: 이 최적화는 1번당 시간만 줄이고 연산 횟수 N²은 그대로. 근본적으로는 많은 MAC을 동시에 처리하는 병렬 처리(NPU)가 필요

**최적화 전/후 비교 (보너스 B1)**
- 변환: `flatten`이 N×N 리스트를 줄 순서대로 이어 붙여 길이 N² 리스트로 만듦. 2차원 `[i][j]` 칸은 1차원 `k = i × N + j` 칸
- 비교 조건: 크기마다 같은 십자가 배열(`make_cross`)을 2차원 그대로 `mac`에, `flatten`한 것을 `mac_flat`에 넣어 각각 10회 평균. 변환 시간은 측정 구간 밖
- 결과: 위 `[최적화 비교]` 표에서 1차원이 2차원 시간의 약 0.6~0.75배. 속도 차이는 칸마다 인덱싱 횟수(패턴·필터 합 4번 → 2번)에서 남
- 점수: data.json 6케이스 × 필터 2개, 12개 점수가 `mac`과 `mac_flat`에서 모두 같음(곱하고 더하는 순서가 같아 부동소수점 오차도 같음)
- 한계: 연산 횟수는 N² 그대로라 시간 복잡도는 O(N²)로 같음. 줄어드는 것은 1번 연산에 붙는 접근 비용뿐

## 5. 과제 목표 정리
**MAC 연산과 AI에서의 중요성**
- 정의: MAC(Multiply-Accumulate)은 두 수를 곱해(Multiply) 누적 합에 더하는(Accumulate) 연산. a ← a + b × c 한 번이 MAC 1회
- 적용: 패턴과 필터의 같은 위치 값마다 MAC을 반복해 N×N 칸의 곱을 모두 더한 값을 점수로 사용. N×N이면 MAC N²회
- AI 모델은 큰 필터 수천 개로 이 계산을 반복해 이미지 한 장에도 MAC이 수억 번 필요. 그래서 MAC 속도가 AI 속도를 좌우하고, MAC을 동시에 많이 처리하는 NPU를 씀

**곱하고 더해서 유사도(점수)를 계산하는 원리**
- 정의: 같은 위치의 두 값을 곱해 모두 더하면, 두 배열에서 큰 값이 같은 위치에 많을수록 점수가 커짐. 그래서 모양이 비슷할수록 점수가 높아 유사도로 쓸 수 있음
- 적용: 0과 1로 된 패턴과 필터라면 곱이 1인 칸은 둘 다 1인 칸뿐 → 점수 = 겹치는 칸 수
- 3×3 십자가 패턴: 십자가 필터와 5칸 겹쳐 5점, X 필터와 가운데 1칸만 겹쳐 1점 → 점수가 큰 필터의 모양으로 판정

**data.json 키 규칙·라벨 규칙과 라벨 정규화 이유**
- 키 규칙: 필터는 `size_N`, 패턴은 `size_{N}_{idx}`. 패턴 키의 N으로 같은 크기 필터를 찾음
- 라벨 규칙: 필터 키는 `cross`·`x`, 정답 `expected`는 `+`·`x`로 같은 모양을 다르게 표기
- 정의: 정규화는 같은 뜻의 서로 다른 표기를 하나의 표준 형태로 바꾸는 것
- 적용: `normalize_label`이 `+`·`cross` → `Cross`, `x` → `X`로 바꿈
- 정규화 이유: 그대로 비교하면 `"+"`와 `"cross"`가 다른 글자라 맞는 판정도 FAIL. 내부에서 `Cross`·`X` 하나로 통일해야 비교가 맞음

**부동소수점 오차와 epsilon 비교가 필요한 이유**
- 정의: 부동소수점은 실수를 `가수 × 2^지수` 꼴로 저장하는 방식. 지수로 소수점 위치가 움직여 "떠다니는 소수점". 가수 자리(52비트)가 유한해 0.1처럼 2진수로 끝나지 않는 수는 잘라서 근사값으로 저장 → `0.1 + 0.2`가 `0.30000000000000004`
- 적용: `size_5_1`에서 0.1을 9번 더한 X 점수는 `0.8999999999999999`, 0.9를 1번 더한 Cross 점수는 `0.9`. 수학적으로는 같은 값인데 저장된 값이 달라짐
- 영향: 같아야 할 두 점수(0.9와 0.8999999999999999)를 `>`로 비교하면 오차 방향대로 한쪽이 이김
- epsilon 비교: 차이가 아주 작으면(`abs(a - b) < 1e-9`) 동점으로 처리해, 오차가 판정을 바꾸지 않게 함

**크기별 연산 시간 측정과 O(N²)**
- 정의: 시간 복잡도 O(N²)는 입력 크기 N이 커질 때 연산 횟수가 N²에 비례해 늘어남을 나타내는 표기
- 적용: N×N 배열은 칸이 N²개라 곱셈도 N²번. N이 2배가 되면 연산은 4배
- 측정: 크기마다 MAC만 10회 반복해 평균 시간(ms). 입력·출력 시간은 제외
- 근거: 3절 성능 표에서 연산 횟수와 평균 시간이 함께 늘어나는 것 확인
